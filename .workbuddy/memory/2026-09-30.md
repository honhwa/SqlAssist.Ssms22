## 設定頁文字跟隨 SqlAssist 語言設定（實作完成，待部署驗證）

使用者回報：設定頁文字不隨「介面語言」下拉框（`sqlAssist.general.language`，英文標籤
`GeneralLanguageTitle = "Interface language"`）切換。原以為是待辦第 3 項，實際上是一個**已實證的機制問題**。

### 根因鏈（全部有實機證據，重查時不必再推）

- 設定頁文字由 **SSMS 殼層**解析註冊檔的 `"@鍵;{packageGuid}"`，用的是**殼層自己的**介面語言
  （優先序：IDE International Settings → OS `GetUserDefaultUILanguage()` → 英文），
  SqlAssist 的語言設定不在那條鏈上。
- 本機：`settings.json` 的 `environment.internationalSettings.language = zh-cn`，
  而 HKCU 的 SSMS／VisualStudio 樹沒有覆寫 → 殼層 zh-CN → 要 `zh-Hans` 衛星；
  我們只出 `zh-Hant` → 退回中性資源（英文）。**這條後備在 `zh-CN → zh-Hans → zh → 中性`。**
- 註冊檔路徑：`%LOCALAPPDATA%\Microsoft\SSMS\22.0_c84cce63\Extensions\<雜湊>\SqlAssist.registration.json`
  （`<雜湊>` 每次安裝都變；1.4.15 是 `ljk05jmd.h3r`）。
- 設定合併進的是**檔案** `…\22.0_c84cce63\privateregistry.bin`（不是登錄），
  使用者設定在 `…\22.0_c84cce63\settings.json`。
- **定義快取**：`…\22.0_c84cce63\UnifiedSettings\DefinitionCache.dat`（VS 的字串池 + 定義），
  它記的是**未解析的 `@鍵` 原字串**，而且 **CacheTag 緊接在註冊檔路徑前面 8 bytes**
  （現行 `08DF1E95B7EABCD7`，舊值已不在）→ **改 CacheTag 就會讓殼層下次啟動重讀註冊檔**。
  這是整個方案的立足點，也是唯一能事前驗證的一環。
- `registration.schema.json` 根層只有 `properties`／`categories`、`additionalProperties: false`；
  四種文字寫法全部走上面那條鏈，**沒有任何 locale 維度**。`ManifestPath` 走 `$PackageFolder$`。

### 做法

切換語言時把安裝資料夾的註冊檔**換成該語言的字面值**，並改寫 pkgdef 的 `CacheTag`（內容雜湊）。

- `Core/Localization/SettingsManifestText.cs`：實體化器（逐行、跳過 `//` 註解、JSON 跳脫、
  可換檔頭說明）＋ `ReadTable`（讀 `.resjson`，用 Core 的 `JsonReader`，它收註解與尾隨逗號）。
- `Ssms22/Settings/SettingsPageManifest.cs`：樣板與文字表都走**內嵌資源**。
  文字刻意**不走 `ResourceManager`**：那要載衛星組件，而探測路徑失效時只會安靜退回中性資源
  ——本專案文件自己記過這件事，不能再賭一次。所以 `SettingsPageText.targets` 把同一批
  `.resjson` 再收一份成內嵌純文字（`WithCulture="false"`、`Type="Non-Resx"`、LogicalName
  `$(RootNamespace).Settings.%(Filename)%(Extension)`）。
- 內容雜湊（FNV-1a 64）當 CacheTag → 內容沒變就不寫檔、不發通知，每次啟動無條件呼叫都安全。
- 代價：殼層在啟動時讀註冊檔，所以**要重新啟動 SSMS**；切換當下發一則 `NotificationKind.Settings`
  的 `Notice` 通知說明。
- pkgdef 是 **UTF-16LE + BOM（CRLF）**，由 VS 的 `GeneratePkgDefFile` 產生；寫回去要保留原編碼
  （`EncodingOf` 讀 BOM 決定）。
