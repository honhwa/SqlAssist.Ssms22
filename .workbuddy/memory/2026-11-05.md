## 修復述詞接續位置（`AND`／`OR`／`HAVING`）按空白鍵沒有補全

- 症狀：`ON `／`WHERE ` 後按空白鍵有配對鍵與全部欄位，接著打 `AND ` 後兩者都消失。
- 根因：`SqlCompletionContextAnalyzer.StartsPredicateClause` 只認 `WHERE`／`ON`，
  使 `ListsScopeColumns = false`；連帶 `SqlCompletionPolicy.IsClosed = false`（空前綴不開清單），
  `SqlCompletionCandidates` 走 `PeekScopeColumns`（只讀快取）而非 `GetScopeColumnsAsync`（查資料庫）。
  配對鍵 `WantsJoinKeys` 在 `AND ` 之後本來就是 true，只是被前兩點擋在畫面外。
- 設計變更：原本 `completion-join-keys.md`／`completion-reopen.md` 與三組測試把「`AND`／`OR`／`HAVING`
  不開清單、只讀快取」定為刻意設計（理由：會蓋掉正要打的 `EXISTS`／`NOT`）。依 `CLAUDE.md`
  工作契約先停下對齊，使用者指定「比照 `ON`／`WHERE`，範圍 `AND`＋`OR`＋`HAVING`」後才動手。
- 修改：`StartsPredicateClause` 白名單加入 `AND`／`OR`／`HAVING`（`WHEN` 仍排除）；
  連鎖效果由既有管線自動生效，未改 `ListsScopeColumns`／`IsClosed`／候選來源的判斷式。
  同步修訂 3 份 docs、4 處程式碼註解、3 組測試期望，並新增 `AND NOT ` 對照案例守住誤開邊界。
  `completion-columns.md` 因 `Check-Docs.ps1` 淨增限制，改為指向配對鍵頁而不重列名單。
- 驗證：RED 8 個 `Core.Tests` 失敗（全為 `Expected True / Actual False`）→ GREEN `Core.Tests` 全綠；
  `Check-TextFiles.ps1`／`Check-Docs.ps1`／`Build-Extension.ps1` 皆 exit 0（命令表 40 個命令、VSIX 40 個檔案）。
  整包 `Run-CoreTests.ps1` 仍 exit 2，來自與本變更無關的既有失敗：
  `SqlAssist.SqlMemory.Sqlite.Tests` 的 `SQLite Error 8: attempt to write a readonly database`（數量 1～3 浮動）
  與 `NotificationIslandTests` 版面度量 `20 vs 20.7`。RED baseline 已存在，列為未解風險。
