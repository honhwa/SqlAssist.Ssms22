## 檢修 InlineRenameCommand（就地改名 @變數）

`a9af6c2 add inlinerename` 帶進來的 `Commands/InlineRenameCommand.cs` 讓整個方案建不起來：
line 22 是檔案範圍命名空間（`namespace SqlAssist.Ssms22.Commands;`），line 23 卻多一個 `{`、
檔尾 782 行多一個 `}`，`error CS1022`；整份檔案從 line 70 起縮排少一層，而且是 CRLF。

### 動了什麼

- **新增 `SqlAssist.Core/Rewriting/SqlVariableRename.cs`**：批次界線、出現位置、EXEC 參數名
  判定、名稱合法性與撞名檢查。Ssms22 只留取焦點、選取、畫底色、寫回緩衝區。
- **重寫 `Commands/InlineRenameCommand.cs`**：改成 `internal static`，走 `OleMenuCommand`
  的 `IsAvailable`，取編輯器改走 `ActiveSqlEditor.Current`（原本自己寫了一份
  `IVsTextManager` + `IVsEditorAdaptersFactoryService`）。
  - 批次界線改用 ScriptDom 的 `TSqlTokenType.Go`，**不再用 regex `\bGO\b`**。
  - `EXEC @rc = dbo.P @p = 1`：`@rc` 是接回傳值的區域變數（可改），`@p` 才是參數名（不可改）。
    原版把兩者一起排除，`@rc` 永遠改不了。
  - `@@` 系統函式一律不給改。
  - 游標命中改用半開區間，貼在名稱右邊界時算在它身上。
  - 還原（Esc）只換回自己改過的那幾處，不再整份文件 `edit.Replace(0, len, _originalFullText)`。
  - 提交失敗（名稱不合法、撞名）不還原也不跳 `MessageBox`，留著讓使用者修一個字，原因寫狀態列。
  - 高亮跟著 `LayoutChanged` 重畫（原版捲動後不重畫）。
  - 空 `catch { //ignore }` 全部改走 `SqlAssistPlatformGuard`；命令入口照
    `SqlAssistCommands` 的慣例用 `SqlAssistDiagnostics.WriteAlways` + `SqlAssistStatusBar`。
- **命令表**：`CommandIds.InlineRename = 0x0221`（右鍵）與 `InlineRenameKey = 0x0222`（F2），
  `Menus.vsct` 加按鈕、IDSymbol、F2 鍵繫結與新的無父群組 `SqlAssistKeyboardOnlyGroup`，
  `ProvideMenuResource` 35 → 36，`SqlAssistCommands` 註冊兩顆。
- **為什麼是兩顆命令**：命令狀態掛在 ID 上。F2 在 SSMS 是「重新命名物件總管的節點」，
  而「最後拿過焦點的 SQL 編輯器」不等於「現在有焦點的那一個」；鍵繫結只能用全域範圍，
  所以 F2 那一顆另外要求 `ActiveSqlEditor.Current.HasAggregateFocus`。共用一個 ID 會讓
  使用者在物件總管按 F2 被搶走，且改的是查詢視窗裡的變數。

### ScriptDom 的兩個坑（實測）

- `TSqlTokenType.Go` = 223，只標在真正的批次分隔上；`'GO'`、`-- GO`、`[GO]` 都不會誤判。
  `TSqlScript.Batches` 也拿得到同樣的邊界。
- **`EXEC` 與 `EXECUTE` 是兩個不同的權杖型別**（`Exec` = 60、`Execute` = 61）。只認前者時，
  全寫的那一種呼叫會被當成一般敘述，參數名整批被改掉。
- 用 PowerShell 查列舉名稱時要注意 `-in`／`-contains` **不分大小寫**：`Goto` 會被 `GoTo` 騙過去，
  要驗就得用 `-cin`／`-cnotin`。
