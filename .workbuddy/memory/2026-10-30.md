## WHERE／ON 之後列出整句來源的欄位（SqlAssist.Ssms22）

- 行為：`WHERE `、`ON ` 之後按空白鍵就開清單，先列整句查詢各來源的**全部欄位**，插入文字一律帶別名
  （沒寫別名時是資料表名稱）；`ON ` 另外把當前來源與前面來源的同名欄位換成整條聯結條件並排到最前面。
- 判定：`SqlCompletionContext.ListsScopeColumns` 由 `keywordPosition == OrderByColumn` 擴充為
  「`Predicate` 而且前一個字是 `WHERE`／`ON`」（`StartsPredicateClause`，讀 `beforeToken` 字串、
  用既有的 `EndsWithKeyword`）。`HAVING`、`AND`、`OR` 的旗標值相同但排除——那幾格接著寫的是條件，
  按空白鍵彈出整份欄位清單會蓋掉 `EXISTS`、`NOT`。目標維持 `Any`。
- 候選：`SqlCompletionCandidates` 拆成 `GetScopeColumnsAsync`（ListsScopeColumns 那一格，允許查資料庫）、
  `PeekScopeColumns`（其餘位置，只讀快取）、`WithJoinKeys`（兩者共用的配對與排序）與 `ScriptColumns`；
  `NeedsScopeQualifier` = ListsScopeColumns 或兩個以上相異限定字。`GetColumnsAsync`（`a.` 那條）維持不補限定字、不配對。
- 介面：`ISqlCompletionMetadata.GetColumnsAsync` 多一個 `indexKeysFirst`（單一來源的述詞起點要索引鍵排前面，
  原本只有 `PeekColumns` 有這個參數）。
- 測試：`SqlCompletionCandidatesTests` 新增「述詞的欄位帶別名並允許查資料庫」（WHERE 與 ON 各一例，
  驗限定字、沒有 Peek、配對鍵排前兩名）與「WHERE 的 CTE 欄位也帶別名」；`單一來源的述詞起點要求索引鍵排前面`
  改驗走查詢那一條。`SqlCompletionContextAnalyzerTests` 的排位案例擴充為八個（含 AND、HAVING 反例），
  `SELECT * FROM t WHERE ` 由不封閉改封閉（policy 與 trigger 測試同步）。
- 文件：`docs/completion-join-keys.md` 補「WHERE／ON 與 ORDER BY 同一種格子、HAVING／AND／OR 只讀快取」，
  並把兩趟的描述改指 `WithJoinKeys`；`docs/completion-columns.md` 只加一句指向配對鍵（該頁 4492 → 4498，
  警告線 4500，同輪刪掉冗句換空間）；`docs/completion-reopen.md` 封閉線索補 `WHERE`／`ON`。
- 驗證：整份方案 0 warning 0 error；Core 26156、Metadata 1060、CompletionAudit 122 全過；
  Ssms22 525/527（`NotificationIslandTests`、`SqlMemoryVisualTests` 兩條既有視覺斷言）、
  Sqlite 144/146（並行寫入，每次清單不同）；Check-Docs 114 份（phrase-generator.md 4837 既有警告）、
  Check-DocLinks 283 個位址、文字檔 1318 檔 0 錯。
- 已知限制：關掉「列出資料庫物件與欄位」時這一格與 `SELECT |` 一樣只剩片語與關鍵字（既有行為）；
  一次按鍵可能為多個來源各查一次第二層（已在快取的不再問）。

## 對照 SQLExtended（P:/github/SQLExtended）盤點功能缺口

- 方法：比對 SQLExtended 的 `MainMenuService.Items` 命令清單與 `README.md` 功能表，逐項在
  `src/` 以關鍵字與檔案清單核實是否有對應實作（`obj`/`bin` 排除）。
- 結論：本專案強在補全／展開／預覽／SQL Memory／搜尋，SQLExtended 有五大塊完全沒有——
  T-SQL 格式化全家桶（Format SQL/Selection/With、Uppercase Keywords、Remove Brackets、
  Insert Semicolons、Formatter 選項）、Align On、Parse Statistics（STATISTICS IO/TIME）、
  四個監控儀表板、Schema Export 與 Validate Schema References；另有 Environment Tabs、
  Object Explorer 節點子選單／Registered Servers 分組、Script Library、DAC 解密、
  結果格線 Find/Go to Column/Aggregates、Rainbow parentheses、Comment tags、無 WHERE DML 保護、
  Schema Cache 管理視窗（含持久化與背景刷新）。
- 部分對應：Qualify Columns（本專案只有補 schema，無逐欄 alias）、QuickInfo 無 row count、
  Script Results as INSERT 僅以 `#temp` + `INSERT ... VALUES` 近似、無 SQL Prompt 片段匯入、
  關鍵字大寫只有輸入時、非命令式。
- 基礎障礙：本專案未引用 ScriptDom 做格式化（只用 `tools/Generate-Keywords.ps1` 反射 token 列舉），
  移植格式化需先決定引用 ScriptDom 或自寫。metadata 目錄是純記憶體，無跨 session 快取。
