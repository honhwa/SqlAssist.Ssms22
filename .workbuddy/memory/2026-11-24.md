## 真正的失敗原因與修正：SSMS 的 MARS 關鍵字別名

- 使用者回報通知為「解密加密模組／Error／#50／2 ms」。`#50` 是通知流水號不是錯誤碼；
  2 ms 代表在本地組連線字串時就失敗，還沒開 DAC。查
  `%LOCALAPPDATA%\SqlAssist.Ssms22\SqlAssist.log` 得到：
  `已解密 0/1 個加密模組－目前連線無法轉成系統管理員專用連線：不支持关键字: "multiple active result sets"。`
- 根因：SSMS 交出的連線字串用帶空格的 `Multiple Active Result Sets`，
  net48 的 `System.Data.SqlClient.SqlConnectionStringBuilder` 在建構時就拒絕這個別名。
  原程式在 `SsmsConnectionSource.TryBuildDacConnectionString` 直接建 builder，因此永遠
  到不了 DAC；`SqlDacConnectionFactory` 的 DAC／探測 builder 也有同一個風險。
- 修正：`SqlDacConnectionFactory.NormalizeKeywords` 用不分大小寫的 regex 把
  `Multiple\s+Active\s+Result\s+Sets=` 換成 `MultipleActiveResultSets=`；所有進 builder
  的入口（DAC、直連埠、探測、連線來源、記憶鍵）都先正規化。DAC 那一端照樣明確關掉 MARS。
- RED 測試：把 `SqlDacConnectionFactory.cs` 連結進 `SqlAssist.Ssms22.Tests`
  （該專案本來就連結產品純原始碼），新增
  `tests/SqlAssist.Ssms22.Tests/Decryption/SqlDacConnectionFactoryTests.cs`，
  涵蓋單空格、多空格與無空格三種寫法。先讓 `NormalizeKeywords` 暫時 return 原字串，
  三條全失敗；恢復後全過。
- 最終驗證：建置 0 warning／0 error；Core 26337、Metadata 1093、SqlMemory.Sqlite 146 全過；
  Ssms22 541 項中 539 過、只剩兩條已知 WPF 視覺斷言。三個檢查通過，
  `Check-TextFiles` 1400 檔。
- 狀態提醒：原移植已被提交為 `79c5539e`；本輪記憶鍵與 MARS 正規化修正仍在工作樹未提交，
  另 `version.json` 由 1.5.13 變成 1.5.15（建置流程產生，需確認是否要保留）。
