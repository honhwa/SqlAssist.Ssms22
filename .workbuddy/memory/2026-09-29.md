## 「設定頁沒有中文版」的根因（已實證）

設定頁文字由**殼層依它自己的介面語言**解析 `@鍵`，**不受 SqlAssist 語言設定控制**。
master 只出 `zh-Hant` 衛星，本機 SSMS 是 zh-CN（`Common7/IDE/2052/` 是全機唯一 MUI 目錄）
→ 宿主文化 zh-Hans → 找不到衛星 → 落回中性資源（英文）。

實證：`%LOCALAPPDATA%\Microsoft\SSMS\22.0_c84cce63\Extensions\4plar4ib.20f\` 底下
`zh-Hant\SqlAssist.Ssms22.resources.dll` 存在，`zh-Hans\` 只有 ScriptDom 的資源。

## 設定頁語言的機制（查證完成，官方依據）

**殼層用哪個 culture 解析 `@鍵;{packageGuid}` 的優先序**（Microsoft 部落格
〈Localizing your VS package resources〉，Allen Anderson）：

1. Tools → Options → **International Settings 指定的語言**
2. 同 1，但用 `SUBLANG_DEFAULT`
3. OS 的 `GetUserDefaultUILanguage()`
4. 同 3，但用 `SUBLANG_DEFAULT`
5. English (1033)
6. 任何找得到的語言

本機實測：`HKCU\Software\Microsoft\SSMS\22.0_c84cce63` 只有 `Licenses`，
**沒有 `International\Language`**（`HKCU\Software\Microsoft\VisualStudio\*` 也沒有）
→ 走第 3 條，`GetUserDefaultUILanguage()` = **zh-CN** → .NET 後備鏈
`zh-CN → zh-Hans → zh → 中性`。我們只出 `zh-Hant` 衛星，所以落到**中性（英文）**。

**所以設定頁永遠是英文，跟 `sqlAssist.general.language` 無關**，也跟
`Thread.CurrentUICulture` 無關（不是執行緒文化，是登錄／OS 那條鏈）。

**註冊檔沒有指定語言的欄位。** 掃過 SSMS 內建 26 份 `*.registration.json` 的文字形式，
只有四種，全部由殼層依上面那條鏈解析：
`@鍵;{packageGuid}`（703 筆）、`@鍵;組件相對路徑.dll`（約 16 筆）、
`#資源ID;{packageGuid}`（127 筆）、純字面值（27 筆）。
`registration.schema.json`（246 KB）的根層只有 `properties`／`categories`／`$schema`，
`additionalProperties: false`；`title`／`description` 的型別是 `string | null`，沒有任何 locale 維度。

**要讓設定頁跟隨 SqlAssist 語言設定，唯一的路是「把註冊檔的文字實體化」**：
改寫 `SqlAssist.registration.json`，把 233 個 `@鍵;{guid}` 換成該語言的字面值，
並更新 pkgdef 的 `CacheTag`。殼層**在啟動時**才讀註冊檔 → **需重啟 SSMS 生效**。

資源檔裡的文字在執行期取得得到：
`new ResourceManager("SqlAssist.Ssms22.Settings.SettingsPageText", asm).GetString(鍵, culture)`
（`SettingsPageText.<語言>.resources` 已用 `WithCulture="true"` 嵌成衛星組件）。

**規模**：註冊檔 91 個設定 + 9 個分類、233 個 `@` 引用；
`SettingsPageText.en.resjson` 231 行、`SettingsPageText.zh-Hant.resjson` 259 行。
繁中／英文的文字**都已經有了**，所以「跟隨設定」今天就能支援這兩種語言；
簡中要等 `zh-Hans` 字串表補齊（＝待辦第 2 項）。

**環境**：部署目錄已由 `4plar4ib.20f` 變成
`%LOCALAPPDATA%\Microsoft\SSMS\22.0_c84cce63\Extensions\14hgvjlz.pal`（使用者可寫）。
