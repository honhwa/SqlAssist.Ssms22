# 2026-11-23

## 優化：表值函式提交時也帶出別名

- 需求：`FROM dbo.fn_LoansByReader` 從補全清單提交時，資料表／檢視會自動帶別名，
  資料表值函式（TVF）沒有。根因：`SqlInsertionText.Build` 在 `ExpandFunctionCall=true`
  時刻意不接別名（括號還沒寫出來），註解說由展開端接，但
  `SqlFunctionCallExpansion.Build` 實際只組 `SqlFunctionCallText.Build`，全鏈路都沒接。
- 先寫 RED：`SqlInsertionTextTests.函式呼叫的別名接在右括號後面`（None/As 兩樣式）
  呼叫尚不存在的 `SqlInsertionText.FunctionCall`，`dotnet build` 回 `CS0117`；
  實作後 Core 26301 項全過。
- Core 改動：新增 `SqlInsertionText.FunctionCall(name, parameters, aliasSuffix, out caretOffset)`
  （`Core/Completion`），把 `SqlFunctionCallText.Build` 的 `name(args)` 與別名字尾組起來，
  caret 仍停在括號內；更新 `SqlAutoAlias.ComposeSuffix` 與 `Build` 的過時註解。
- Ssms22 接線：`SqlAsyncCompletionCommitManager` 在提交時用同一個 `SqlAutoAlias.ComposeSuffix`
  算出字尾，交給 `FunctionCall` 補空括號，並經 `SqlCommitExpander.Resolve` 傳進
  `SqlFunctionCallExpansion`；展開填引數時用同一支重組，別名不會被第二次編輯吃掉。
  `NoteInsertedClose` 的位置改為「插入文字結尾 − 1 − 字尾長度」，避免自動配對跳過別名
  而不是跳過 `)`。
- 文件：`docs/completion-insertion.md` 增「資料表值函式的別名接在右括號後面」一節
  （該頁 3430 → 約 3880 字元，仍在 4500 警告線下）；`SqlInsertionTextTests` 舊註解同步改。
- 驗證：solution 建置 0 warning／0 error。四套測試：`Core` 26301、`Metadata` 1093、
  `SqlMemory.Sqlite` 146 全過；`Ssms22` 536/538，失敗為
  `NotificationIslandTests.所有內容對齊同一條圖示中線與文字起點`（穩定失敗）與
