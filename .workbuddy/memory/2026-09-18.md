## 查 GetBuildVersion 的值

`GetBuildVersion` 不是 VSSDK 內建：`Microsoft.VsSDK.targets` 只把 manifest 裡
`|%CurrentProject%;<目標名>|` 的 `<目標名>` 當成「要在被參考專案上執行的 MSBuild 目標」
（`OutputGroupToResolve`），值是那個目標的傳回值。目標本身由 Nerdbank.GitVersioning 提供
（`build/Nerdbank.GitVersioning.targets:102`，`Returns="$(BuildVersion)"`），來源是
`version.json` 的 `version` + git height + commit id。

取得值（在沙箱實測皆可）：

```bash
dotnet msbuild src/SqlAssist.Ssms22/SqlAssist.Ssms22.csproj \
  -t:GetBuildVersion -getTargetResult:GetBuildVersion -v:quiet
# => 0.18.1.24002
# 加 -getProperty:BuildVersion,AssemblyVersion,AssemblyFileVersion,
#   AssemblyInformationalVersion,NuGetPackageVersion,PublicRelease 可一併讀出
```

免建置的替代：讀 `obj/x64/Release/net48/extension.vsixmanifest` 的 Identity Version
（此檔已展開，`merged.source.extension.vsixmanifest` 則保留原佔位符）。nbgv CLI 未安裝。

沙箱注意：`subprocess.run` 帶 `shell=True` 且參數自己加引號時，MSBuild.exe 會回
「filename, directory name, or volume label syntax is incorrect」；改用 list 參數、
不加引號、`shell=False` 即可。腳本：`artifacts/get-build-version.py`。

## ON／WHERE 的配對鍵

需求：打完 `ON` 之後自動把「當前對象」與前面來源的同名（含去分隔符同名）欄位配成整條
聯結條件排到清單最前，其餘欄位照舊；生效位置 `ON`／`WHERE`（含 `AND`／`OR`／`HAVING`）。
確認過的取捨：配對鍵優先其餘照舊、同名＋去分隔符同名、插入 `b.CopyNo = a.CopyNo`、ON 與 WHERE。

新增 `src/SqlAssist.Core/Completion/`：

- `SqlJoinKeySource`、`SqlJoinKey`、`SqlJoinKeyMatch`、`SqlJoinKeyMatcher`。
  `Pair(sources)` 先按限定字分群，當前群組＝最後一群；每個欄位只配**最近**的前一群，
  兩側限定字同名者跳過（`CanPair`）。回傳 `SourceIndexes`（當前群組的來源索引）＋`Pairs`；
  **配不到也照樣回索引**（索引講的是「當前對象是誰」）。同名限定字先合併，但兩者皆 null
  不併（兩個沒有別名的衍生資料表是兩個來源）。`Normalize` 沿用 `FuzzyMatcher.SqlDelimiters`
  （該欄位由 private 改 internal），全分隔符名稱跳過。
- `SqlKeywordPositionAnalyzer.IsPredicateStart`：
  `position != Any && (position & Predicate) != None`。**關鍵陷阱**：`Any` 是 `[Flags]`
  把所有位置 OR 在一起，`ON a.CopyNo = |` 的位置分析回 `Any`，只靠位元交集會誤判成述詞
  起點，於是插入整條條件變成 `= a.CopyNo = b.CopyNo`。
- `CompletionTarget.Predicate`：允許類別與 `Any` **完全相同**，只差空前綴也參與。少了它，
  `ON `／`WHERE ` 打完當下 target 仍是 `Any` → 整份不參與（`InitializeCompletionCore`
  的觸發字元數門檻與 `IsValid`）→ 清單根本不出現。`SqlCompletionContextAnalyzer` 在
  `target == Any && qualifierPath is null && IsPredicateStart(...)` 時收斂；**有路徑的
  限定字不動**（`WHERE c.|` 要交給範圍解析收斂成 `Column`）。
- `SqlInsertionText.Qualify(name, qualifier, settings)` 改公開，供 `SqlJoinKey` 兩側共用。
- `SuggestionMatcher.JoinKeyBonus = 3`：加在**類別層之內**（欄位 35+3=38 ≤ Snippet 40，
  不破四層不變式）；3×128 大於最近用過 64＋長度上限 63。

`Ssms22/Connections/SqlMetadataService.cs`：`GetCachedScopeColumns` 簽名從
`(IReadOnlyList<SqlColumnSource>)` 改成吃 `SqlCompletionContext`，分兩趟——第一趟只收名稱
（Names 來源用 `source.Names`，Table 來源用快取，**解析不到也給空集合佔位**以保住索引），
`SqlJoinKeyMatcher.WantsJoinKeys(context) ? Pair(...) : Empty`；第二趟
`BuildScopeColumnSuggestions` 用 `match.SourceIndexes` 的 HashSet 認出當前對象，配對到的
欄位換上整條條件的 `InsertionText` 並前置進 `keys`，其餘進 `columns`，最後
`keys.AddRange(columns)`（同一筆欄位只留一處）。

## 沙箱測試執行的坑（本次踩到，下次照做）

- `dotnet test <方案> -p:Platform=x64 -v q` 會回 **`Zero tests ran`／exit 5**，四個組件全中。
  不要用 `-v q`；要就照 `tools/Run-CoreTests.ps1` 的 `dotnet test <方案> --configuration Release`。
- **net48 測試不能被 `dotnet <dll>` 叫起來**（缺 `hostpolicy.dll`／`runtimeconfig.json`），
  必須直接跑 `.exe`。net10.0 的則用 `dotnet <dll>`。
- 測試框架是 **xUnit v3 + Microsoft.Testing.Platform v2**：`--filter "*Class*"` 這種 VSTest
  語法不吃（會回 `Zero tests ran`）。要確認某個測試有沒有被編進去，用 `--list-tests` 重導到
  檔案再讀，別用 `--filter`。
- 測試主控台的**中文是 cp936**，用 UTF-8 讀會亂碼；`io.open(...,encoding='cp936')` 才對。
  另外 `subprocess.run(capture_output=True)` 抓不到 `--list-tests` 的輸出（要改用檔案重導）。
- `rm` 這個 shim 是壞的（`safe_delete_main: command not found`，exit 127）——刪暫存檔用
  python `os.remove`。
