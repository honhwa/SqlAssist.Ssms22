## Enter 帶出排名第一筆（未選擇直接提交）

使用者需求：在 `FROM`、`ON`、`WHERE` 等位置彈出物件清單後，已匹配到項目但沒按方向鍵選擇時，
按 Enter 要帶出第一個匹配到的物件。

- 根因：平台對 Tab 與 Enter 一律視為提交，沒有「未選擇」這個狀態——它總有一筆選取。
  真正會出錯的是那筆選取停在**上一次篩選留下來的索引被夾住**的位置，與當下名次無關。
- 解法（單檔單處）：`SqlAsyncCompletionItemManager.Filter` 的 `FilteredCompletionModel`
  改成六參數版本，傳 `UpdateSelectionHint.Selected` + `centerSelection: true` + `uniqueItem: null`，
  每次重新篩選把正式選取固定回索引 0。必須用 `Selected` 不能用 `SoftSelected`：
  平台定義軟選取「只用 Tab 或滑鼠提交」，**Enter 不算**。
- 這一項備份版已經做過，本次是被目前分支覆寫掉的（`git diff --no-index` 一比即見），
  連同 `docs/completion.md` 的說明段落一起補回（另補一句涵蓋 `FROM`／`ON`／`WHERE` 情境）。
- 不需新增命令處理常式：`SqlTabCommandHandler` 的 Enter 分支刻意回 `false`（維持換行語意），
  提交語意全在 `IAsyncCompletionCommitManager` 與選取狀態上，改選取即可。
- 驗證：全方案 `-p:Platform=x64` 0 警告 0 錯誤；Core 2502／Metadata 924／SqlMemory 146
  全綠；Ssms22 482/483（唯一失敗仍是既有的通知島字形斷言）；`Check-TextFiles.ps1`
  與 `Check-Docs.ps1` 皆 exit 0。
