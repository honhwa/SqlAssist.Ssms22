## EXEC 展開改成三段式（宣告 → 呼叫 → 取回輸出）

使用者需求：EXEC 帶出預存程序時，先宣告所有參數並依型別賦值，有預設值的用模組的預設值，
最後把所有 OUTPUT 參數用 SELECT 顯示出來。

- 難點在「**預設值本身**」：`sys.parameters.has_default_value` 對 T-SQL 模組永遠是 0，
  必須剖析 `OBJECT_DEFINITION`。原本只有 `Find` 回傳「有名稱的集合」（布林），
  新增 `Resolve` 回傳「名稱 → 字面值」，`Find` 改成包在 `Resolve` 外面。
- 只收**可安全內嵌的字面值**：數字、字串、`NULL`、變數、簡單識別字（`GETDATE()`、`ON`）。
  帶運算子的（`1 + 2`、`'x' + 'y'`、`GETDATE() + 1`、`-1`）整組**放棄**——
  收成前半段會組出語法正確而值算錯的宣告，比留給使用者填糟糕。
- **踩到的兩個真 bug**（都已修）：
  1. `GETDATE` 少了後隨的 `()`。`Token.Text` 只有名稱本身，接出來是
     `DECLARE @d DATETIME = GETDATE;` —— 那是語法錯誤。修法：識別字後面若是一對
     空括號，用 `ValueWithParentheses` 從原文切（保留原文空白）。
  2. **數字／字串分支直接 return，完全沒檢查後面還有運算子**，於是 `@A = 1 + 2`
     被收成 `1`。修法：三個分支統一收口到「取值 + 確認它是單一個詞元」
     （下一個詞元必須是同一層的 `,`、`)`、`AS`、`RETURNS` 才算）。
- 排版三段：所有參數各一行 `DECLARE @x AS 型別 [OUTPUT] 初始值;`（初始值對齊同一欄）、
  `EXEC` 只傳 `@x = @x`、有 OUTPUT 時空一行後 `SELECT @x AS x, …;`。
  宣告一律寫 `AS` —— 純量函式傳回參數 `DECLARE @rc AS INT` 少了 `AS` 是語法錯誤。
- 游標從「呼叫那行的值」搬到「**第一個宣告的初始值**」。位置直接用前綴組出來
  （`DeclarationHead` 長度 + 對齊空白 + 1），**不要**從整段長度往回扣——
  最後一列尾巴有幾樣東西取決於縮排是不是空的，少扣一項就偏移一格，
  而偏移一格在畫面上看不出來。這是本 turn 實際踩到的第三次偏移。
- 教訓：**對齊寬度不要手算**。我連續三輪把期望字串的空格數寫錯。正解是跑一個
  臨時探針把實際輸出逐行印出來（`len={l.Length}` + 原樣字串），照抄進斷言。
  探針放在 `.workbuddy/tmp/Probe`，用完刪掉。
- 另一個自己造的錯：以為 `nvarchar` 無預設值時是 `NULL`，其實是 `N''`

## 第五輪：`DECLARE` 不寫 `OUTPUT`、賦值加 `=`、呼叫端補 `OUTPUT`

使用者原話：「declares时不需要output,并且赋值时要加上"=", 在下方exec存储过程时,output的参数要加上OUTPUT」

上一輪剛做完三段式，這一輪是對它的三處微調。**結果長這樣**：

```text
DECLARE @LoanId AS int              = 0;
DECLARE @Days AS int                = 7;
DECLARE @NewDueDate AS datetime2(7) = NULL;
EXEC dbo.usp_Loan_Renew @LoanId = @LoanId,               -- int
                        @Days = @Days,                   -- int，選擇性
                        @NewDueDate = @NewDueDate OUTPUT -- datetime2(7)

SELECT @NewDueDate AS NewDueDate;
```

### 核心洞察：`OUTPUT` 的語意歸屬

`OUTPUT` 是**呼叫端**的語意——「這個變數要接回傳值」——不是變數宣告的一部分。
`DECLARE @x INT OUTPUT` 本身就是語法錯誤，它只能寫在 `EXEC` 那一行的引數上。
上一輪把它寫在宣告上是錯的。

反過來說，`OUTPUT` 參數**仍然要宣告**：每個參數在呼叫端都是變數，
少宣告任何一個，那一句連編譯都過不了。所以是「宣告所有參數、但宣告不寫 OUTPUT」。

### 改動清單（`src/SqlAssist.Core/Statements/SqlProcedureCallText.cs`）

| 位置 | 改動 |
|---|---|
| `DeclarationHead` | 拿掉 `OUTPUT` 後綴，只留 `DECLARE {name} AS {type}` |
| `AppendDeclarations` | 對齊空白後多接一個 `"= "` |
| `assignments` 迴圈 | `IsOutput` 時寫成 `{name} = {name} OUTPUT` |
| `CaretOffset` | `+ 1` 改成 `+ " ".Length + "= ".Length`（多算 `= ` 兩個字元） |
| class 摘要 + 三處 remarks | 補上「OUTPUT 屬呼叫端語意」的理由，改掉「少了 AS 是語法錯誤」的舊敘述 |

`AS` 的存在理由也跟著改了：從前寫「純量函式傳回參數少了 `AS` 是語法錯誤」，
**那是錯的**——`DECLARE @x AS INT` 與 `DECLARE @x INT` 都合法。
寫 `AS` 真正的作用是**讓型別的位置對齊**：`DECLARE @Name AS nvarchar(50)` 與
`DECLARE @Note AS nvarchar(200)` 的型別起點才會落在同一欄。

## 第六輪：區塊骨架自動配對（BEGIN…END、TRY…CATCH）

使用者原話：「增加自动闭合如单引号,[,{, BEGIN END, TRY CATCH等」

**先問清楚再動手**：單字元配對（`(` `'` `[` `"`）其實**早就做完了**，
四方向齊全。真正缺的是多字元區塊。用 AskUserQuestion 確認了三件事：

| 問題 | 選擇 |
|---|---|
| 觸發方式 | **選一段文字再打 `BEGIN` 包夾**（不是打完就自動補） |
| 涵蓋範圍 | `BEGIN`…`END` **與** `TRY`／`CATCH` 都要 |
| 開關 | **新增獨立開關** `autoPairBlocks` |

### 成果

```text
    UPDATE dbo.Loan
    SET CopyNo = 1;          ← 選取這兩行，打 BEGIN
      ↓
    BEGIN
        UPDATE dbo.Loan
        SET CopyNo = 1;
    END
```

打 `BEGIN TRY` 則一次補出五行（`END TRY`／`BEGIN CATCH`／`END CATCH`）。

### 三個關鍵決定

1. **TRY/CATCH 一次補完四行**，不先給 TRY。分兩次補的話中間那段時間緩衝區裡是
   `BEGIN TRY` 少了 `END TRY` 的**語法錯誤**，SSMS 會把整段標紅。
2. **CATCH 裡不預放 `THROW;`**——那是錯誤處理的**策略**，骨架只管語法。
   要 `THROW;` 的人走片段 `tc`。
3. **只認 `BEGIN` 與 `BEGIN TRY`**。`BEGIN TRAN`／`BEGIN DIALOG`／
   `BEGIN CONVERSATION TIMER` 都不需要 `END`，猜錯要使用者刪三行、
   猜對只省一次換行——**不對稱，所以寧可不補**。

### 時機是這個功能的真正難點

單字元配對在**按鍵當下**就有答案；區塊不行，要等 `BEGIN` 五個字元都進緩衝區
才分得出 `BEGIN` 與 `BEGIN TRY`。而 `TypeCharCommandArgs` 跑的時候
**那個字元還沒進去**（與自動大寫要在插入**之前**改寫是同一個時序——
`SqlKeywordCasing` 的 remarks 就寫著這件事）。

**解法**：用既有的 `TextViewDispatch.AfterCurrentCommand` 排在這一輪命令之後再問，
與 `SqlCompletionReopen.AfterSeparator` 用同一個排程機制。
**我第一版寫成在 TypeChar 裡直接呼叫，那是錯的**——會少看一個字元。
這一條是讀 `SqlKeywordCasing`／`SqlCompletionReopen` 的 remarks 才發現的。

### 測試抓到的兩個真 bug（都是我自己造的）

1. **`BEGIN   TRY`（多個空白）→ null**。我聲稱「正規化」但 `EndsWithKeyword`
   做的是逐字元比對，只認得**剛好一個空白**。改成由後往前比對、遇到關鍵字裡的
   空白就吃掉一到多個空白。**教訓：remarks 裡寫的行為要對得上程式碼。**
2. **關鍵字起點用「游標減關鍵字長度」推**——空白數不拘時這個等式不成立。
   改成由比對函式回傳起點，型別 `SqlBlockMatch { Closer, Start }`。
   `SqlBlockCloser.Keyword` 的 remarks 裡也補上「長度不能用來回推起點」。

第三個失敗是**測試期望寫錯**（我以為換行會被正規化，其實原樣保留）。改期望。
