需求：游標停在變數上按 F2，選取 `@` 之後那一段直接改；改的同時同一上下文裡的同名變數

**架構照 F12 那一套走**，兩半分工：

關鍵判斷（踩過才知道的）：

- **範圍取批次（`GO` 邊界）不是敘述、也不是整份指令碼**。區域變數活到批次結束，所以
  「同一個變數」的邊界正好是 `GO`；取整份會把另一個批次裡同名的變數一起改掉。
- **名稱比對不分大小寫**，改完每一處拼法統一成剛打的那一種。
- **字串與註解不算出現處**：靠 `SqlTokenizer.Tokenize`（不含註解多載）本來就不會把它們
  讀成 Variable 詞元，不必另外判。
- **只有 `IsValidName` 過關時才鏡射**：打到一半的 `@a b` 不該留在其他出現處。
- **`@@` 全域變數回 null**：那不是使用者取的名字。
- **命令狀態只問「有沒有 SQL 編輯器」**，不問「游標在不在變數上」——後者要詞法分析整份
  指令碼，而命令狀態每一次按鍵都會被問一次。這是 F12 的同一條界線。
- **`SqlTokenizer.IsIdentifierStart`／`IsIdentifierPart` 由 private 改成 public**，讓
  「這個名字會不會被讀成一個識別字」只有一份答案；自己抄一份字元表遲早對不上。
- **不用 `IMultiSelectionBroker`**（原生、復原一格）：本擴充沒用過它，而這裡沒有 SSMS
  可實測，猜錯等於改壞整份指令碼。只用已經在用且有測試的 `ITrackingSpan`＋一次
  `CreateEdit`／`Apply`＋`Selection.Select`。**取捨是 Ctrl+Z 的粒度**（先還原其他出現
  處、再還原游標那一處），已寫進 `docs/variable-rename.md`。

### 5. 剩下那一條：150% 螢幕縮放，不是產品錯，也還沒決定怎麼修

## 工具：這個 repo 的測試要怎麼跑、怎麼二分（本輪踩出來的）

- **過濾要用 `--filter-class`／`--filter-method`，不要用 `--filter`。**
  測試宿主是 xUnit v3 + Microsoft.Testing.Platform，`--filter` 只吃 **VSTest 語法**

- 二分競態：`--max-threads 1`（單執行緒）＋ `--filter-not-class` 逐一排除。
- 直接跑 `tests/<專案>/bin/Release/net48/<專案>.exe` 最快，不必每次都過 `dotnet test`。
- `artifacts/run_full.py` 會把原始輸出留在 `artifacts/full-test-output.txt`（失敗明細在裡面）。

## 預覽命中高亮改成黃色系（使用者定案）

**問題**：同一筆命中，清單列是**固定記號黃**（`SqlHighlightText` 用
`ThemeBrush.MatchHighlightBackground`），預覽卻是**強調色系**（`SqlScriptTheme` 呼叫
`MatchPalette.Create(ColorOf(ThemeBrush.AccentBorder, …), …)`）。而
`docs/search-highlight.md:39-40` 明文要避免這個症狀：「各寫一份的症狀是同一個搜尋字在同一個
視窗的兩塊看起來不是同一件事」。

**兩份文件互相矛盾**（這才是根因）：
- `themes.md:36-46`（Design B）：清單用固定黃；預覽**用同一個色系**，只依指令碼底色調明度
  （`Fade`，上限 60%）。
- `search-highlight.md` + `text-marks.md` + `MatchPalette`/`TextMarkColors`（Design A）：
  以強調色為種子、兩級都落在深的那一側（亮度上限 0.18）。

**決定（我問過使用者，選「改成黃色系，與清單一致」）**。

**實作時發現我在選項說明裡提的機制是錯的**：`TextMarkColors.Pair(Mark, surface)` 有一條明文
規則「底色亮度上限 0.18」（`text-marks.md:29`），把黃餵進去會被壓成**暗橄欖色**，跟清單那個亮黃
仍不是同一個觀感。真正對應 `themes.md:44-46` 的是那兩個**無人呼叫**的私有方法
（`SqlScriptTheme.Highlight`／`Fade`）。所以改用後者，並如實回報偏離。

**改法**（`Preview/SqlScriptTheme.cs`）：
- `MarkFill(mark, background, target)` = `EnsureGraphicContrast(Fade(mark, background, target), background)`；
  `Fade` 加上 `target` 參數，方向抽成 `Away(background)`。
- 一般命中 `target = 3`；目前那一處 `target = 3 × TextMarkColors.LevelSeparation`（沿用既有常數）。
- **`Separate` 是必要的**：深色主題下黃本來就離底色很遠（約 11.5:1），兩個門檻第一次都過，
  兩級會拿到同一個顏色；再往遠離底色的方向推開到 `LevelSeparation`。做法與
  `TextMarkColors.Pair` 把弱級往暗推同一個形狀。
- 字色 `ThemeColorMath.EnsureTextContrast(surface.Foreground, fill)`——保留指令碼自己的前景，
  讀不到才校正。**不能用 `TextMarkColors.Ink`**：它在讀不到時一律回白，而黃底需要的是深字。
- 高對比沿用原本的反白 + 系統選取。

**連帶清理**：刪 `UI/MatchPalette.cs`（改完就沒有消費者）、`ThemeBrush.MatchBackground`／
`MatchForeground`／`MatchCurrentBackground`／`MatchCurrentForeground` 四個成員與字典項、
