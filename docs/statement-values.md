# 展開的欄位、參數與預留值

本頁處理 INSERT 欄位、EXEC 參數、預留值與對齊；安全寫回與 MERGE 見 [整句展開](statement-expansion.md)，
函式的括號與引數見[函式呼叫](function-call-insertion.md)。

## 哪些欄位插不進去

四種，漏掉任何一種的症狀相同——展開出來的 `INSERT` 一執行就錯：

| 排除 | 判斷依據 |
|---|---|
| `IDENTITY` | `sys.columns.is_identity` |
| 計算欄位 | `sys.columns.is_computed` |
| `rowversion`（舊名 `timestamp`） | 型別名稱；`sys.columns` 沒有這個旗標 |
| 時態與帳本資料表的 `GENERATED ALWAYS` 欄位 | `COLUMNPROPERTY(…, 'GeneratedAlwaysType')` |

最後一種刻意不讀 `sys.columns.generated_always_type`：那一欄要 SQL Server 2016 才有，
直接 SELECT 它會讓整份欄位查詢在更舊的執行個體上變成語法錯誤，而
`TryLoad` 會把它降級成「這一輪沒有資料」——於是欄位建議、萬用字元展開與結構預覽
會在那些伺服器上**一起安靜地消失**。`COLUMNPROPERTY` 對認不得的屬性名稱回傳 NULL，
舊版因此自然得到 0。

一個欄位都撈不到時**整個放棄**，維持只插入名稱：同義字在 `sys.columns` 裡沒有列，
組出 `INSERT INTO syn () VALUES ()` 比什麼都不做糟糕得多。這與 `SELECT *` 不做
部分展開是同一條理由。

## 值先填什麼

三條，順序不能對調：

1. 有 `DEFAULT` 條件約束 → `DEFAULT`
2. 可為 NULL → `NULL`
3. 其餘 → 依型別的預留值（`''`、`N''`、`0`、`0x`、`NEWID()`）

`VALUES (DEFAULT)` 對「沒有預設值而且 NOT NULL」的欄位是執行期錯誤，所以第一條
只能給真的有 DEFAULT 條件約束的欄位。

日期時間型別給 `NULL` 而不是 `''`：空字串轉成日期是 1900-01-01，那是一個**執行得動的
錯值**，而預留值要的正是「看得出來還沒填」。`NULL` 在 NOT NULL 的欄位上會失敗，
而失敗看得見。

型別讀不出來（`SELECT … INTO #Loan` 投影出來的欄位，
見[指令碼宣告的資料表](script-tables.md#投影出來的暫存資料表)）時走第二條：那些欄位一律當成
可為 NULL，值填 `NULL`，註解也不寫型別那一段。讀不出型別不是漏了什麼——它要追到最
內層的資料表才算得出來，而 `NULL` 是唯一不會替使用者猜錯內容的預留值。

## 參數的選擇性從定義讀，不從中繼資料讀

`sys.parameters.has_default_value` 對 T-SQL 模組**永遠是 0**——那一欄只對 CLR 模組
有效。所以「哪些參數可以省略」只能剖析 `OBJECT_DEFINITION` 的參數清單，
在 `Core/Statements/SqlModuleParameterDefaults`。

定義是第三層資料，本來不在按鍵路徑上；但提交也不在按鍵路徑上，而且
`GetDetailAsync` 的同一次呼叫本來就會把欄位、參數與定義一起帶回來，因此不多付
任何一次往返。讀不出來就少標幾個「選擇性」，不猜——猜錯會讓使用者刪掉一個其實
必填的參數。

## `DECLARE` 的初始值取模組的預設值

同一趟掃描有第二個出口 `Resolve`，多帶回**預設值本身**。展開成 `DECLARE` 需要它：
省略一個有預設值的參數，呼叫時用的就是那個值，換成型別的預留值（數字 `0`、
字串 `N''`）在語法上成立，卻把使用者設定的預設值換掉了——那是一句跑得動、
結果卻不對的呼叫。

只收**可以原樣嵌進 `DECLARE` 的字面值**：數字、字串、`NULL`、變數，
以及不會被求值成運算式的簡單識別字（`GETDATE()`、`ON`…）。帶運算子的
（`@b INT = 1 + 2`、`@s NVARCHAR(10) = 'x' + 'y'`、`@d DATETIME = GETDATE() + 1`）
整組**放棄**：收成前半段會組出 `DECLARE @b INT = 1`，語法正確而值算錯，
比留給使用者自己填糟糕得多。少收一個只是退回型別的預留值。

`GETDATE()` 要連那一對括號一起帶回去——`Token.Text` 只有名稱本身，
少了括號 `DECLARE @d DATETIME = GETDATE` 是語法錯誤。

猜錯的代價不對稱，因此每一關都往「放棄」倒：留 `NULL` 只是少一點方便，
猜一個值卻可能安靜地寫錯資料。

## `EXEC` 展開成三段

| 段 | 內容 |
|---|---|
| 宣告 | 所有參數各一行 `DECLARE @x AS 型別 = 初始值;` |
| 呼叫 | 只寫 `@x = @x`，最後一列不加逗號；`OUTPUT` 參數再補一個 `OUTPUT` |
| 取回 | 有 `OUTPUT` 時 `SELECT @x AS x, …;`，沒有就整段省略 |

**所有**參數都要宣告，不只是 `OUTPUT` 那幾個。從前只有 `OUTPUT` 需要變數，
所以只宣告那一種；現在呼叫端每一個都是變數，少宣告任何一個，那一句連編譯都過不了。

`OUTPUT` 只寫在**呼叫那一行**，宣告上一律不寫。那是呼叫端的語意——「這個變數要接
回傳值」——不是變數宣告的一部分，`DECLARE @x INT OUTPUT` 本身是語法錯誤。
宣告一律寫 `AS`（`DECLARE @rc AS INT`）：寫不寫 `AS` 都合法，寫它是為了讓型別的
位置在長度不一的參數名稱之間對齊起來。

`OUTPUT` 參數的值只在變數裡，SSMS 的「訊息」頁看不到；不 `SELECT` 出來，
使用者就得到一個永遠讀不到的結果。

`SELECT` 與 `EXEC` 之間空一行：兩者是獨立的兩段，黏在一起時那個 `SELECT`
看起來像是呼叫的一部分。輸出欄位一行一個，`AS` 後面接去掉 `@` 的名字。

沒有參數的模組不展開（展開起來與只插入名稱一模一樣）。擴充預存程序在
`sys.parameters` 裡也沒有列，同樣落在這一條。

「EXEC 展開時包含選擇性參數」關掉之後，這份選擇性清單改當篩子用：標成選擇性的
整列不展開。省略它們本來就是合法的呼叫方式，而參數二三十個的程序展開出來有一半
是使用者接著要一行一行刪掉的。讀不出定義時清單是空的，於是每個參數都算必填——
方向與上一段一致：寧可展開得多，也不要因為讀不到定義而把該填的參數吞掉。
篩完一個不剩時退回只插入名稱，走的是「沒有參數的模組不展開」同一條路。

## 續行的對齊

`EXEC` 的續行對齊到第一個參數所在的欄，每一列的 `@` 因此落在同一個位置；
宣告那一段同理，每一列的初始值落在同一欄。代價是名稱長的模組會把整段推向右邊。
`INSERT` 的欄位與 `VALUES` 一律每列一個，
而且**不跟**「SELECT * 展開後的欄位排版」那個設定走——那個設定的三種排法都在權衡
「一行讀不讀得完」，而這裡的兩份清單是**成對**的：第三個欄位對第三個值，
攤成一行就對不起來，而對不起來的代價是把值填錯格。

縮排取語句所在行的前導空白，整段重複到每一行，定位字元原樣保留：每一行前面放的
都是同一串字元，在定位寬度不是 4 的機器上也對得齊。第一行是使用者原本那一行，
前面沒有任何前導文字，縮排因此從第二行起才出現。

`EXEC` 與 `EXECUTE` 照使用者原本寫的帶回去。統一改寫成 `EXEC` 也合法，但那是他
沒有要求的改動——與展開萬用字元時保留他自己寫的限定字是同一條。

## `INSERT INTO` 與單獨的 `INTO` 必須分開

`SELECT * INTO #tmp` 的 `INTO` 後面是一個**還不存在的新名稱**，在那裡展開骨架會蓋掉
使用者正在取的名字。所以認的是 `INSERT INTO` 這兩個字，而不是 `INTO` 一個字。

替換的範圍從 `INSERT` 開始，不是從 `INTO`——只從 `INTO` 開始換會在編輯器裡留下一個
孤零零的 `INSERT`。
