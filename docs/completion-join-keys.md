# ON 與 WHERE 的配對鍵

述詞的起點——`ON`、`WHERE`、`HAVING` 的正後方，以及 `AND`／`OR` 之後——清單除了敘述
看得到的全部欄位，還會把**當前對象**的同名欄位換成整條聯結條件排到最前面：

```sql
SELECT * FROM dbo.Loan l JOIN dbo.Copy c ON |
→ c.CopyNo = l.CopyNo        ← 排在最前，選了就寫完整條
→ c 與 l 其餘的欄位照舊列在後面
```

挑選項就等於寫完條件（插入 `c.CopyNo = l.CopyNo`，游標留在後面接 `AND`），不必先挑
一邊再回頭補另一邊。規則在 `Core/Completion/SqlJoinKeyMatcher`，插入文字與說明欄在
`SqlJoinKey`；這些欄位本來就會列出來，見[欄位建議](completion-columns.md)。

## 當前對象是誰

**游標前最後加入的那個來源**，不是清單裡某一張表的名字。這一問有答案，是因為範圍分析
回傳的來源順序就是它們在敘述裡出現的順序：

```sql
FROM A a JOIN B b ON |        → 當前對象是 b
… JOIN C c ON |               → 換成 c
… WHERE |                     → 沿用的是同一條規則，還是 c
```

## 同名怎麼認

**同名加去分隔符同名**，忽略大小寫：`CopyNo`、`copy_no`、`COPY_NO` 是同一個名稱。
分隔符表與模糊比對的詞界共用同一份（`FuzzyMatcher.SqlDelimiters`，`_`／`#`／`@`／`.`…），
所以不必另外維護一張。整個名稱都由分隔符組成的跳過——那樣的兩個名稱互相配對等於說
所有名稱都同名。

## 配對規則

- **只配最近的前一個來源。** `A a JOIN B b … JOIN C c` 之後，`c` 的欄位接的是 `b`，
  接 `a` 是同一個名稱卻跨過了一張表；近的配不到才往外找。
- **同名限定字的來源先合併。** `FROM (SELECT Id, * FROM T) d` 攤平出兩筆都叫 `d` 的
  來源，不合併的話當前來源只拿得到寫死的那幾個名稱，而它明明還有一整套欄位。兩個都
  **沒有**限定字的衍生資料表不併——那是兩個來源，併起來會讓其中一個的欄位憑空跑到
  另一個身上。
- **兩側限定字相同的來源跳過。** 同一個名稱配自己不是聯結條件。
- **配不到就什麼都不做。** 名稱沒有交集時清單維持原樣，這條路徑不猜。

## 插入的文字

兩側都冠限定字（`SqlInsertionText.Qualify`）：這裡的欄位名稱**一定**有兩個來源在競爭，
裸名在敘述裡模稜兩可，寫出來會執行失敗。一般欄位那條「相異限定字兩個以上才補名字」
管不到這裡——同一份敘述就是因為有兩個來源才配得出對。

`GetCachedScopeColumns` 為此分成兩趟（`Ssms22/Connections/SqlMetadataService`）：第一趟
只收各來源的欄位名稱（資料表來源用**已經在快取裡**的，解析不到就給空集合佔位，索引才
對得上來源），配對算完才走第二趟建建議項——配對結果會改掉其中幾筆的插入文字，名稱沒
收齊就不知道誰跟誰同名。

配對鍵只加在**當前對象**那幾個來源上，由 `SqlJoinKeyMatch.SourceIndexes` 指認：同名
欄位在別的來源裡也有，靠名稱比對會把前面那張表一起改掉。同一筆欄位只留一處——被配對
到的欄位移到最前面，不再留在原位；兩個位置各放一筆的話，清單看起來一樣，選了卻寫出
完全不同的東西。

## 排名

加成加在類別層**之內**（`SuggestionMatcher.JoinKeyBonus`）：欄位 35 加 3 是 38，仍在
這一層的預算裡（最高是 Snippet 的 40），所以翻不過比對品質那一層——打了前綴之後命中的
好壞仍然先說話；但 3×128 大於最近用過 64 加長度懲罰上限 63，同一個位置上配對鍵因此
壓得過任何非配對欄位。分層見 [completion.md](completion.md#清單內容與排名)。

## 只有述詞的起點才算

認的是**述詞的起點**（`SqlKeywordPositionAnalyzer.IsPredicateStart`），不能只問
「含不含 Predicate 位元」：`SqlKeywordPosition.Any` 是 `[Flags]` 列舉，把所有位置 OR
在一起，條件左邊寫完之後——`ON a.CopyNo = |`——位置分析回的就是 `Any`，靠位元交集會把
那裡也當成述詞起點，插入整條條件就寫出 `= a.CopyNo = b.CopyNo`。

`SELECT |` 與 `FROM |` 也不在內：那些位置要的是欄位或資料表本身，把兩張表之間的聯結
條件塞到最前面只是佔位。

空前綴的述詞起點另外收斂出 `CompletionTarget.Predicate`，讓清單在打完 `ON` 的當下就
自己出現，見[範圍與重開](completion-reopen.md#詞元一結束就把清單重開)。
