# 加密模組定義

本頁包含 `WITH ENCRYPTION` 模組在 F12 與物件結構裡如何取回本文、前提條件與失敗行為；一般模組定義的來源與排版見[定義指令碼](definition-scripts.md)，建議清單刻意不讀本文。

## 何時會解密

只有「看定義」的四條路會試：編輯器 F12、結構預覽、SQL Search 的定義預覽，以及 SQL Search 的「移至定義」。失敗時保留原本的「取不到定義」註解，不把已經查到的欄位與參數一起丟掉。自動補全、QuickInfo 與索引建立都不碰 DAC。

開關是設定頁的「解密物件結構中的加密模組」（`sqlAssist.general.decryptEncryptedModules`），**預設關閉**。它關掉時上面四條路與沒有這項功能時完全一樣。

## 前提

- 登入必須是 `sysadmin`：DAC 只讓它進，而且解密會短暫 ALTER 物件。
- 遠端執行個體要 `sp_configure 'remote admin connections', 1; RECONFIGURE;`；SQL Server Express 要服務以 trace flag 7806 啟動才會監聽 DAC；Azure SQL Database 沒有可連的 DAC。
- 目前連線要留有憑證。Windows 驗證可直接用；SQL 驗證若 SSMS 沒有把密碼留在連線字串裡，會明確回報「改用 Windows 驗證或讓 SSMS 記住密碼」，不猜密碼，也不把 Entra token 塞進連線字串。

## 做法與理由

SQL Server 把模組本文與一條依物件識別導出的金流做 XOR；金流與本文內容、長度無關。所以同一個物件的兩份不同定義可以還原原文：

1. 從 DAC 讀原密文。
2. 用已知明文的假定義短暫 ALTER 物件，在同一次伺服器端批次裡再讀一次密文，然後 ROLLBACK。密文放在資料表變數裡，回復後仍留著；連線中途斷掉由引擎回復，假定義不會留下。
3. 兩份密文與假定義明文做 XOR，再驗證結果以 CREATE／ALTER 開頭且提到該物件；不像模組定義就丟掉。

假定義必須用 `ALTER` 執行，但 XOR 要用同一句子的 `CREATE` 形式——引擎儲存並加密的是 CREATE 行為。反過來只會對前五個字，其後全部錯一位，而且仍然回傳字串。因此關鍵字與主體永遠分開建，不拼成同一句。

批次帶 `SET LOCK_TIMEOUT 5000`：ALTER 要 Sch-M 鎖，等待時會把該程序的新呼叫者一起堵在後面。全處理序同時只放行一條 DAC，最多等 30 秒；忙碌的 DAC（17810／17809）重試兩次，其餘失敗不重試。

## 記憶與回報

結果按 `伺服器|資料庫|schema.name|modify_date` 記憶，物件改過才重讀。失敗也記：登入被拒記到工作階段結束，DAC 被占用記 5 秒，完全連不上記 2 分鐘；「清快取」或重新整理建議會清掉。

每次真正嘗試的結論進通知列（成功數／總數或第一個原因），完整原因是寫進診斷記錄；記憶命中不再送通知。你看到的定義開頭已改成 CREATE，交給原有的排版層再改成 ALTER，與一般模組一致。

## 尚未確認

核心 XOR 與假定義的有測試鎖住 CREATE／ALTER 不對稱；DAC 實連、ALTER 回復與各版本 SQL Server 的端口探測沒有伺服器端測試，須在實機確認。
