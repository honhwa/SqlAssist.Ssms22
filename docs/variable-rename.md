# F2 變數重新命名

游標停在區域變數上按 F2 就地改名字，同一批次裡的每一處一起改，按 ↑／↓／Enter 結束。
本頁只講這一個功能；物件定義的 F12 是另一件事，見[移至定義](go-to-definition.md)，
鍵繫結與命令表怎麼接見[殼層命令](shell-commands.md)。

## 操作

1. 游標停在 `@readerId` 上（名稱中間或結尾都可以），按 **F2**。
2. `@` 之後那一段被選取起來，直接打新的名字。
3. 打的同時，同一批次裡每一處同名變數跟著改。
4. 按 **↑**、**↓** 或 **Enter** 結束；按 **Esc** 放棄並還原原名稱。

游標離開名稱（滑鼠點走、按 ←／→）也算結束，與其他編輯器的就地重新命名一致。不這樣
的話，使用者點到別處之後這一份還在改，下一個字會落到他沒在看的地方。

## 範圍是批次

T-SQL 的區域變數活到批次結束，`GO` 之後那個名字就不存在了，所以「同一個變數」的邊界
正好是 `GO` 的邊界：

| 取法 | 症狀 |
|---|---|
| 敘述 | 漏掉宣告與其他敘述裡的用法，改完編不過 |
| 整份指令碼 | 把另一個批次裡恰好同名的變數一起改掉，而那是兩個變數 |
| **批次**（採用） | 與變數的實際生命週期一致 |

名稱比對不分大小寫：預設定序下 `@Id` 與 `@id` 是同一個變數，改完每一處的拼法會統一成
剛打的那一種。只看詞法單元，所以字串與註解裡的 `@x` 不算出現處——`'@readerId'` 與
`-- @readerId` 都不會被改到。

`@@` 開頭的全域變數不是對象：那不是使用者取的名字。

## 撞名與不合法都整批還原

結束時檢查新名字，不通過就整批還原成原名稱，並在狀態列說明原因：

- **撞名**：同一批次裡已經有另一個變數叫這個名字。比對的是**其他**變數，所以改回原本
  的名字、或只調整大小寫，都不算撞名。
- **不合法**：不是合法的識別字（空白、減號、數字開頭…）。判斷用
  `SqlTokenizer.IsIdentifierStart`／`IsIdentifierPart`，不另外抄一份字元表——抄一份的話，
  症狀是名字打得出來、詞法分析器卻不把它當成一個詞元。

打字過程中名稱還不合法時**不鏡射**：那個中間狀態（`@a` 打成 `@a b` 的那一瞬間）不該留
在其他出現處，而下一個按鍵通常就修好了。

## 為什麼自己鏡射而不用多重選取

編輯器的 `IMultiSelectionBroker` 乍看正好合用，原生而且復原是一格。沒有採用是因為本擴充
沒有別的地方用過它，而這個功能在開發環境裡沒有 SSMS 可以實測——猜錯的代價是「按下 F2
之後整份指令碼被改壞」。現在只用本擴充已經在用、行為已知的幾樣東西：`ITrackingSpan`、
一次 `CreateEdit`／`Apply` 的原子替換、`Selection.Select`。

**取捨是復原的粒度**：打一個字是一次編輯、鏡射是另一次，所以 Ctrl+Z 會先還原其他出現
處、再還原游標那一處，不是一次還原整個重新命名。換來的是每一處的結果都對。

## 接線與驗證

- 命令表把 **F2** 綁在 `cmdidRenameVariable` 上，全域範圍，理由與 F12 相同。SSMS 的查詢
  視窗沒有把 F2 綁在任何編輯器命令上，所以沒有第二條路可以攔。
- 命令狀態只問「有沒有 SQL 編輯器」。問「游標是不是在變數上」要詞法分析整份指令碼，
  而命令狀態在每一次按鍵、每一次閒置都會被問一次。
- 進行中的 ↑／↓／Enter／Esc 由 `SqlShellCommandFilter` 交給 `SqlVariableRenameSession`；
  其餘按鍵照常轉傳，打字與 Backspace 維持原行為。
- 純邏輯（找變數、列出現處、驗證新名）在 Core 的 `SqlVariableRename`，因此測得到；編輯器
  那一層連不到 SSMS 服務，只能在實機上驗收：F2 → 改名 → Enter，以及改成既有變數名時
  要看到狀態列的訊息且文字整批還原。
