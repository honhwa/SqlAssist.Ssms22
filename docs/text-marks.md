# 文字標記的底色

把**一小段**文字整個染起來、要它從周圍跳出來的那一類顏色：搜尋命中的兩級與區塊端點的高亮。
推導在 `Ssms22/UI/TextMarkColors.cs`。命中自己的語意與導覽見[命中高亮](search-highlight.md)，
取色與生命週期見[主題連動](themes.md)。

## 不走這一層的

鋪滿整行或整個區間的分類色：差異比對的加／刪底、區塊範圍。**面積決定屬於哪一類**——那一類
要的是融入（底色淡、原本的文字顏色照舊讀得出來），這一類要的是跳出來（底色實、字色重算）。
兩類混成一份的下場是差異檢視變成一整片深色塊，而命中仍然淡到看不見。

使用者在設定裡指定過的顏色也不走這一層，只做對比校正：套上這裡的亮度帶等於把他挑的顏色改掉。
區塊端點因此只有**一個顏色都沒自訂**時才走。

## 兩組

差別在底色落在明度軸的哪一側。**螢光筆黃與金黃都是固定的，不從強調色推導**：標記說的是
「這一段被劃起來了」，與主題色無關；跟著強調色走的那一版，同一個搜尋字會隨主題變成紫的、
綠的、藍的，而使用者要從命中讀到的只有「這幾處對上了」。

| 用在哪 | 底色 | 字色 |
|---|---|---|
| 搜尋命中的兩級 | 固定亮黃 | 深字 |
| 符號端點（括號、方括號、字串引號） | 固定金黃 | 固定白 |
| 關鍵字端點（BEGIN／END、TRY／CATCH、CASE） | 強調色推導 | 淺字 |

符號端點與命中讀的是同一件事，底色卻落在相反的一側：兩者常同時出現在同一行——在編輯器裡找
一個值，而那個值正好包在引號或括號裡——同色的話「命中停在哪裡」與「配對的兩端在哪裡」疊成
同一塊顏色，而這兩件事要分得開。

深色組的規則，每一條都來自實機上看得到的症狀：

- **底色一律落在同一側**（深）。佈景強調色的明度會**跟著佈景翻轉**——淺色佈景是深紫，深色
  佈景是亮紫。直接拿它當底色，配對的字色也跟著翻轉，端點在深色佈景上就變成亮底深字，和同一
  行上的命中長得一樣。壓在深的那一側之後，字色才固定走淺的那一端。
- **字色走這一側能到的最純的那一端**，4.5 只是下限不是目標。一達到 4.5 就停的那一版停在
  中灰，而中灰配飽和彩底是所有組合裡最難看的一個。表面自己的前景色讀得到就留著它——
  **符號端點例外**，它是唯一兩個通道都定死的一組：底色調亮到 3:1 那一檔之後，淺色佈景的深字
  在金黃上讀得到（約 5.7:1），沿用「留著它」會讓同一個標記在兩套主題上變成黃底黑字與黃底白字
  兩種組合。

分級只發生在命中的那兩級：**同一組的兩級只動明度與飽和，不離色相那一族**。目前那一處是同一
支筆在同一處再劃一層（疊第二層會往金黃偏），不是換一個顏色。

## 門檻

| 項目 | 值 | 理由 |
|---|---|---|
| 關鍵字底色亮度上限 | 0.18 | 再亮下去淺色字過不了 4.5 |
| 金黃底色亮度上限 | 0.29 | 白字 3:1 的邊界是 0.30，取 0.29 是留給 8 位元捨入的餘裕；再往深就退回偏褐的那一版 |
| 深色組底色與表面 | 1.45 | 深色佈景上表面本身就在深的那一側，中間只剩這麼窄一段；差額補在色度與字重 |
| 命中底色與表面 | 1.25 | 這一組靠色相——白紙上的螢光筆看得到是因為它是黃的；要到 1.45 只能把亮黃壓成土黃 |
| 命中底色亮度帶 | 0.5–0.85 | 推出這一段就不像螢光筆了，所以推不進去時停在邊上 |
| 兩級之間 | 1.3 | 表面亮到必須把兩級一起壓深時，壓的動作會把兩者擠在一起；目前那一處得再推開一級 |
| 符號端點字色與底色 | 3.0 | 端點只有一個字元寬，認得出來靠的是底色跳不跳；而白字要 4.5 就得把黃壓成褐色 |
| 字色與底色 | 4.5 | 其餘各組的下限 |

推開表面的方向是**遠離它**：表面比這一塊暗就往淺推，反之往深推。往固定方向推的那一版，
在深色佈景上會先穿過表面的亮度再往黑走，推完是一塊幾乎全黑、色相也沒了的方塊。
金黃那一支實際上只往深推——它的上限就是起始亮度，往淺推等於再往白字的可讀性讓一步，而那一組
已經讓過一階了（4.5 → 3.0）。

## 高對比

沒有中間色可調，也沒有亮度帶可用：兩級換成反白與系統選取色，差的是色相不是明度。
對比比值在那裡判不出差別，所以驗收只要求兩者不同。
