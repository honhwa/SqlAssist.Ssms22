# 貼上值清單

本頁包含剪貼簿上的一欄值怎麼變成 T-SQL 字面值、兩種貼上形狀、哪些值不加引號與
什麼時候整段拒絕。反方向的「複製成 IN 條件」見[結果格線](result-grid.md)。

## 兩個命令

都在**查詢視窗右鍵選單**上，差別只有頭尾那兩個符號：

| 命令 | 貼出來的樣子 | 什麼時候用 |
|---|---|---|
| 貼上為 IN 條件 | `IN (` 開頭、`)` 結尾，自成一段述詞 | `WHERE` 後面還是空的 |
| 貼上為值清單 | 只有值與逗號 | `IN (` 已經打好、游標停在括號裡 |

兩顆都**沒有鍵繫結**，也不是攔截 Ctrl+V。Ctrl+V 是最常按的鍵之一，要在貼上的當下猜
「這次要不要轉」猜錯就把正常的貼上弄壞，而畫面上看不出是擴充動的手腳。要綁鍵自己到
**工具 → 選項 → 環境 → 鍵盤**搜 `SqlAssist.PasteAsInPredicate`。

剪貼簿的內容由使用者決定，所以兩個命令都只讀剪貼簿、不碰結果格線——與
結果格線那一組命令的方向相反。

## 值怎麼變成字面值

一行一個值，值之間補上逗號。文字一律加 `N` 前綴並把單引號跳脫成兩個，
與結果格線的 `SqlValueLiteral` 同一組規則，理由也一樣：少一個 `N`
是把非拉丁字元換成問號而不報錯。

```sql
IN (
    N'A01',
    N'B02'
)
```

「`IN (` 已經打好、游標停在括號裡」時用「貼上為值清單」，前後各留一個換行與一層內縮，
所以接上去就是上面那個形狀。

## 哪些值不加引號

剪貼簿上沒有型別，只能看值長什麼樣，所以判準**刻意保守**——只認純十進位整數或小數，
可帶一個正負號與一個小數點。加引號最多多一次隱含轉換，不加會安靜地換一個值：
`007` 會變成 `7`、`2024-03-04` 在別人的 `DATEFORMAT` 下會變另一天、
`0x1F` 會變成 `0`、千分位的 `1,234` 連逗號都留不住。這些一律當字串。

| 值 | 結果 |
|---|---|
| `42`、`-7.5`、`+0.25` | 不加引號 |
| `007`、`0x1F`、`1e5`、`2024-03-04`、`1,234` | 加引號與 `N` |
| `1.`、`.`、`-` | 加引號與 `N` |
| 空行 | 跳過，不算一個值 |

## `NULL` 一律當字串

剪貼簿分不出真正的 `NULL` 與一個內容剛好是 `NULL` 這四個字的字串——SSMS 自己的複製
把兩者都寫成長度 4 的 `NULL`，實測記在[格線輸出](result-grid-generation.md)的
「為什麼不走剪貼簿」。這裡選當字串：當關鍵字的話 `x IN (NULL)` 恆為 UNKNOWN，
條件永遠不成立，使用者明明挑了那一列卻永遠比不到。

## 什麼時候整段拒絕

- **剪貼簿是多欄（Tab 分隔）的表格。** 取第一欄會安靜地丟掉其餘欄位的值。
  整列貼回 SSMS 就是這個情形，訊息會直接說請只複製單一欄。
- **內容沒有可用的值。** 空白行不算一個值。剪貼簿裡不是純文字、或正被別的程式
  占用（開啟失敗）也走同一條路，訊息會說出是哪一種。
- **插入位置唯讀，或游標停在虛擬空白上。** 後者請先移到文字之間。
- **選取範圍是框選。** 框選是好幾段不連續的範圍，取代掉會一起蓋掉每一段。

尾端空的欄位不算多欄，避免逼使用者重新選取一次。

兩個命令都只依「SqlAssist 開著、而且游標在 SQL 編輯器裡」決定要不要變灰，
**不先開剪貼簿**：`QueryStatus` 在每一次開右鍵選單時都會走過，而開剪貼簿是跨程序
呼叫，來源帶著一大段選取範圍時要幾百毫秒。真的沒有東西可按時，按下去會在狀態列
說明白——從選單按下去卻什麼都沒發生，等於故障。
